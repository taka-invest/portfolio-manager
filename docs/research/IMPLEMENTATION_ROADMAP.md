## 1. 技術構成の方針

| 論点 | 方針 | 理由 |
|---|---|---|
| 分析エンジン | **Python（pandas）の研究スクリプトを手元のPCで実行**。結果の集計表だけをアプリに渡す | 研究は月1回程度で十分。常時動くサーバーは不要（Cloud Run は導入しない） |
| 生データの保存 | 手元の `data/`（`.gitignore`）に保存。公開リポジトリには入れない | FREDのPre-Approval系列・Cboe・ICEは再配布不可。リポジトリは公開 |
| 結果の保存 | 集計結果（分布の要約・件数・信頼区間）を Firestore の本人専用ドキュメント `users/{uid}/research/{id}` に管理スクリプトで書き込む。版番号・データ期間・計算日時・コードのコミットを付ける | アプリは読むだけ。ルールで本人のみ読める（既存の許可リスト方式） |
| 定期実行 | 当面は手動（月1回）。GitHub Actions は使わない | 公開リポジトリのActionsではデータや成果物の扱いに注意が必要。デプロイ用サービスアカウントも保留中 |
| 現在値（毎日の判定） | 既存の自前API（`/api/market`）で取る現在値と、保存済みの集計表を画面で突き合わせる | 研究計算をサーバーで毎回しない |
| APIキー | FREDのキーは手元の環境変数（`.env`、gitignore）。サーバーには置かない | 研究は手元でのみ実行 |
| モデルの版管理 | 結果ドキュメントに `version`・`dataThrough`・`commit`・`params` を記録。閾値の変更は新しい版として保存し、上書きしない | 後から閾値をいじる「データスヌーピング」を防ぐ |

## 2. 段階計画

### P0-A：研究用データの取得（1〜2日）
- 内容：`research-engine/`（Python）に取得スクリプトを置く。FRED API で VIXCLS・NASDAQ100・NASDAQCOM・DEXJPUS（USD/JPY）を取得し、手元の `data/` に保存する
- 依存：FREDのAPIキー（無料、本人が取得）
- テスト：
  - 取得件数と開始日の検査（VIXCLS 1990-01-02〜 など）
  - 欠損日（休場）の扱い
  - 生データが git に入らないことの検査
- 受入基準：スクリプト1本で再取得でき、データ期間が表示される。リポジトリに生データが無い

### P0-B：VIX≥30 イベント研究（3〜5日）
- 内容：`MARKET_TIMING_MODEL_DESIGN.md` §2 の戦略 S0〜S4 を計算する
  - 約定は**翌営業日の終値**で近似（FREDは終値のみ）
  - 円建て・ドル建て
  - 手数料を控除
  - ブートストラップ信頼区間
  - 結果を Firestore に保存し、アプリに「研究結果」ページを追加する
- テスト：
  - 小さな合成データで各戦略の約定日・価格・機会損失を手計算と一致させる
  - 先読みがないことの検査（t日の判定に t+1 以降のデータを使わない）
- 受入基準：
  - 戦略ごとに中央値・下位5%・最大逆行幅・機会損失・件数・信頼区間が表示される
  - イベントごとの個別結果の表がある
  - 「有意差なし」の場合はそう表示される
  - 前提（データ・約定・手数料・限界）が画面に書かれている

### P0-C：市場レジーム判定（3〜4日）
- 内容：§1 のルールで日々のレジームを分類し、レジーム別の 20/60/250営業日後の分布（件数・独立局面数付き）を計算して保存する。市場分析の画面で、現在のレジームと過去の分布を表示する
- テスト：分類ルールの境界値、独立局面の数え方、現在値と保存済み表の突き合わせ
- 受入基準：「過去の同じ状態から60営業日後：中央値 x%、下位5% y%（n=件数、独立局面 k回、1986〜2026）」が出る。データが古い・取れないときは表示しない

### P0-D：段階買付・今日やることへの連携（1〜2日）
- 内容：今日やることガイドと段階買付の画面に、現在のレジームとP0-Bの要点を参考情報として1行で出す
- 受入基準：数値は研究結果ページと一致する。売買の株数・順番は変えない（参考情報のみ）

### P0-E：株価・VIXの取得元の方針決定（並行・調査1〜2日）

## 4. テストの方針

- 研究コード：合成データで手計算と一致させる。先読み禁止の検査。乱数（ブートストラップ）は種を固定
- アプリ：既存の単体・ブラウザーテストに、結果の表示・前提の注記・データが古いときの非表示を追加
- 研究結果の再現性：版・データ期間・コミットから同じ結果が再計算できること

## 5. 最後の5つの問いへの回答

**1. Portfolio Managerに最も不足している重要機能は何か**
判断の根拠を、過去のデータで検証して数字で示す仕組みが不足している。今の市場シグナル・参入シグナル・投資判断は閾値の表示にとどまり、「過去にこの状態から何が起きたか（件数・分布・下落幅）」を返せない。売買計算・固定ルール・段階買付・予想表示という実行側の土台はすでに揃っている。

**2. どのサービスのどの機能を最優先で参考にすべきか**
- **Portfolio Visualizer の結果の見せ方**：要約指標、成長曲線とBuy&Hold比較、ドローダウン、ローリングリターン、「手数料・税を含まない」等の注記。P0-Bの研究結果ページにそのまま効く
- 次点は **Koyfin／TIKR の予想とバリュエーションの見せ方**：実績と予想の連続表示、アナリスト数と幅、過去パーセンタイル。データではなく見せ方だけを参考にする

**3. 買い場・売り場の確度モデルのために最初に実装すべきもの**
FRED（VIXCLS・NASDAQ100・USD/JPY）による長期データの取得と、VIX≥30のイベント研究。即時・段階・正常化待ち・下げ止まり確認の4つを、翌日約定・円建て・機会損失・件数と信頼区間つきで比べる。確率モデルは、この結果と件数を見てから判断する。

**4. 見送るべき機能**
- 有料の複数年アナリスト予想：$200/月〜
- 上場廃止銘柄を含む全銘柄バックテスト：$630/年〜
- 市場騰落数を使う指標：無料の長期履歴なし
- 機械学習：イベント数が少なく過学習のおそれ
- 配分の最適化：固定配分と矛盾
- チャートパターン認識

1〜3（予想・全銘柄データ・騰落数）は、P0の研究で有望な結果が出た場合にだけ、有料化を再評価する。

**5. 最初の実装フェーズとして完成させるもの**
P0-A〜D：データ取得 → VIX≥30イベント研究の結果ページ → レジーム判定と過去分布の表示 → 段階買付・今日やることへの参考表示。
並行して、Yahoo非公式エンドポイントからの移行方針（P0-E）を決める。完成の目安は、オーナーの問い「VIX30突破直後に買うか、待つか」に、件数・信頼区間・前提・限界つきで答えられる状態。
