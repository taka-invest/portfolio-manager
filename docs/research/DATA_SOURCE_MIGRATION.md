## 3. 案

### 案A：EODHD Historian に一本化（推奨）$19.99/月（年 $199）
- 置き換えるもの：
  - Yahoo の全用途（現在値、日足、指数、USD/JPY）
  - FRED（研究データ）
- 利点：
  - 規約が私的な保存・分析を明示的に認めている [確認済み]
  - 30年以上の履歴が1つの取得元にそろう
  - 研究とアプリで同じデータを使える
- 未確認の点：`VIX.INDX` と `USDJPY.FOREX` が取れるか。無料版（1日20回）で実際に試してから契約する
- 注意：
  - 株価の現在値は15〜20分遅れる。注文計算に使う株価は、これまでどおり Finnhub `/quote` を使う
  - USD/JPYは約1分の遅れで、注文用の条件（20分以内）は満たす
- 作業：オーナーが登録と支払いをし、キーを `functions/.env` に追記する。その後、取得部分の置き換え（数PR）、研究の取り直し、結果の再アップロード

### 案B：無料の範囲で縮小
- 現在値は Finnhub `/quote`。指数は ETF（QQQ・SPY）で代用する
- 日足の履歴を使う機能（チャート、RSI、200日線）は、無料版の制限（Massive：2年・毎分5回、保存条件は未確認）の範囲に縮める
- **VIXのライブ値がなくなる**。相場の状態の判定と、VIXを使う市場シグナルが成り立たない
- 研究は FRED を使い続けるので、保存の問題が残る（§4 の対策が必要）

### 案C：現状維持
- 規約上のリスクを承知で Yahoo を使い続ける。推奨しない
- Yahoo の遮断や仕様変更で、予告なく止まる可能性もある

## 4. FRED（研究データ）の当面の扱い

案Aに移るまでの対策として、次を提案する。
1. **研究スクリプトを「取得 → 計算 → 破棄」に変える**：CSVを `data/` に保存せず、メモリ上で計算して、集計結果だけを残す
2. **手元に保存済みの FRED の CSV（`data/raw/fred/`）を削除する**。オーナーの承認後に行う。完全に消える操作だが、元データはFREDから再取得できる
3. **アップロード済みの結果から FRED の生の値を除く**：
   - 対象は、イベントごとのVIX値と、現在のVIX・指数・200日線の値
   - 統計値（リターンの分布・件数・区間）だけを残し、再アップロードする
4. 案Aに移ったら、研究を EODHD のデータで取り直す（版を上げる）

## 5. Fear & Greed
- 公式の取得手段がなく、ボット遮断も始まっている。**表示をやめる**か、取れたときだけ「非公式・参考」として表示するかを選ぶ
- 研究（バックテスト）には、もともと使っていない
