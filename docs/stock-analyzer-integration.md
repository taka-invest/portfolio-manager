# Stock Analyzer → Portfolio Manager 統合監査・移行計画

- 作成日: 2026-11-23
- 移行元: https://masya-stock-analyzer.netlify.app/
- 移行先: https://taka-invest.github.io/portfolio-manager/portfolio_manager.html
- 移行先リポジトリ: \`taka-invest/portfolio-manager\`
- **重要: 現時点でStock Analyzerのサイト内容・ソースは未取得。移行元の実機能について断定しない。**
- Status: **Phase 0 完了（移行先の確認）／Phase 1 ブロック中（移行元ソースを待機）**

## 基本方針

Portfolio Managerを唯一のアプリに統一する。銘柄分析・市場分析と既存の保有管理・取引管理を共存させるが、旧アプリをそのままiframeで埋め込むことは最終形としない。データソース、ティッカー識別子、通貨、更新時刻、保存・復元の規則を一本化する。

旧Netlifyサイトは全機能の移植と検収が済むまで維持する。**バックアップ検証前の削除は禁止**する。

## Phase 1: 移行元の取得・監査

### 必要な一次資料

1. 最優先はStock Analyzerの**GitHub/GitLabなどの元ソースのURL、もしくはZIP**。Netlify画面で紐づくGitリポジトリを確認する。
2. 元コードがない場合、Netlify管理画面の **Deploys → 成功したデプロイ → 詳細ヘッダーの Download → Download ready** で公開ファイル一式のZIPを取得する。Netlify公式ドキュメント: https://docs.netlify.com/deploy/manage-deploys/manage-deploys-overview/#download-a-deploy
3. **NetlifyのデプロイZIPはビルド済み成果物であり、元のTypeScript/Reactソース・環境変数・秘密鍵・Functionsの実装をすべて含むとは限らない。** GitリポジトリとNetlifyの設定も別途確認する。
4. ブラウザーにだけ保存される旧アプリのユーザーデータがあれば、Stock Analyzer側で安全にエクスポートしてバックアップする。
5. **APIキー・アクセストークン・認証シークレットをこのチャットや公開GitHubのIssue/PRへ貼らない。** 環境変数はキー名と利用目的のみを記録する。

### 監査の成果物

- 実画面と機能の完全一覧：データ取得、入力、指標計算、保存、出力、認証、エラー処理
- API／外部依存一覧：提供元、エンドポイント、ライセンス・レート制限、キャッシュTTL、使用箇所
- 移行元／移行先の重複・独自機能マトリクス
- 移行元→移行先のデータスキーマと変換ロジック（事前プレビュー＋承認＋ロールバック）
- Netlify専用機能の移植方法と費用対比

## Phase 3: 機能別段階移植

推奨順序（移行元監査で変更可能）:

1. **表示のみの分析画面**。既存Portfolio Managerの保有情報の変更や注文実行はしない。
2. **共通ティッカー・価格・財務データアダプタ**。\`source\`、\`asOf\`、\`currency\`、\`period\`、\`basis\`などの来歴を保持。スナップショットとライブデータを混同しない。
3. **保有銘柄、ウォッチリスト、企業評価との連携**。\`PLTR\`等の銘柄を一度だけ管理し、画面間では同じ識別子を使う。
4. **移行元データのインポート**。フォーマット検証、差分プレビュー、重複排除、バックアップ、承認を含める。
5. **UI/UX統合**。PC/スマホ、暗色／明色、画面切替の互換性を確認。

### 実装上の制約

- 移行元未取得のため、存在が確認できない指標や画面は**実装しない**。
- 証券口座の実保有・目標配分・原価・確定取引履歴への書き込みは既存の確認済みパスを通す。
- 外部APIが失敗した場合に古い価格を「最新」と見せたり、欠損した財務数値を0埋めしたりしない。
- 株価データの時点と財務諸表の対象期間の違いを明示する。
